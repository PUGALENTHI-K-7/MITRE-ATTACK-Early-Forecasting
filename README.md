# Explainable Early Forecasting of Next MITRE ATT&CK Techniques

A Python research project that studies whether the **next distinct MITRE ATT&CK technique** can be forecast from a partial, chronologically ordered sequence of Windows host events.

This repository accompanies the research manuscript:

> **Explainable Early Forecasting of Next MITRE ATT&CK Techniques from Partial Windows Host-Event Sequences**

The experiments use the Windows-APT 2025 dataset. The project compares frequency and Markov baselines with neural sequence models and evaluates prediction performance, early-warning lead time, warning coverage, attention-masking faithfulness, and model ablations.

> **Reproducibility note:** The manuscript reports result values and key experimental settings, but does not provide the original implementation source code or specify every implementation choice. This repository implements an explicit, repeatable protocol consistent with the manuscript. A new run may produce different numerical results. The files in `outputs/` are the actual outputs of the run committed to this repository; they should not be represented as an exact reproduction of the manuscript's reference values.

## Project overview

Given a prefix of Windows host-event observations, the pipeline attempts to predict the next distinct technique label from a selected set of 12 MITRE ATT&CK techniques. It evaluates both predictive quality and whether a sustained warning can be produced before the target technique appears in the observed telemetry.

### Models

1. **Most Frequent** — a simple reference baseline.
2. **First-order Markov model** — estimates the next technique from one preceding technique.
3. **Second-order Markov model** — estimates the next technique from up to two preceding techniques.
4. **Causal Transformer** — a neural sequence baseline using causal attention.
5. **GRU with temporal attention** — the attention-equipped recurrent model used for temporal explanation analysis.
6. **GRU without attention** — used for the attention ablation experiment.

### Evaluation

- **Prediction performance:** Macro-F1, Top-3 accuracy, and macro false-positive rate (FPR).
- **Early warning:** median warning lead time and coverage per target technique.
- **Explanation faithfulness:** compares probability changes after masking attention-ranked positions with changes after random-position masking.
- **Ablation and prefix sensitivity:** compares GRU variants and performance for different maximum prefix lengths.

### Automatic extraction

The default configuration points to the archive included in this repository. If the expected period CSV files are not already present in the local `data/` directory, the pipeline extracts the archive automatically when you run `run_all.py`.

From the repository root, run:

```powershell
python run_all.py --epochs 15
```

### Manual extraction (optional)

You can also extract the included archive yourself before running the experiment:

```powershell
New-Item -ItemType Directory -Force "data\Windows-APT 2025 A Dataset for APT-Inspired Attack"
```

Then run `python run_all.py --epochs 15` from the repository root. If you already have the dataset extracted elsewhere, use the `--data-dir` argument and provide the directory that directly contains the per-period CSV files.

## Requirements and installation

- Windows, Linux, or macOS
- Python 3.10 or later recommended
- Internet access to install Python dependencies (and to download the dataset separately if you do not use the included archive)
- Free disk space for the extracted CSV files, prepared data, model checkpoints, and result files

The experiments can run on a CPU; a GPU is not required. Runtime depends on the computer and the number of epochs.

### Windows with VS Code / PowerShell

Open a terminal in the repository root—the folder containing `run_all.py`—and execute:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell prevents activation, use the virtual environment's Python executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Run the complete experiment

Run all experiment stages using the paper's maximum of 15 epochs:

```powershell
python run_all.py --epochs 15
```

This command prepares the dataset, trains and evaluates the prediction models, calculates warning lead time and coverage, runs attention-masking faithfulness analysis, and performs the GRU ablation/prefix-sensitivity analysis. Results are written to `outputs/` by default.

### Quick smoke test

To check the workflow with fewer training epochs before running the full experiment:

```powershell
python run_all.py --epochs 2
```

A two-epoch run is a workflow check only. **Do not substitute its results for the full experiment in a paper.**

### Select a different data or output directory

If the extracted dataset is stored elsewhere, specify its directory:

```powershell
python run_all.py --data-dir ".\path\to\extracted\dataset" --epochs 15
```

To choose a different output directory:

```powershell
python run_all.py --output-dir ".\my_outputs" --epochs 15
```

You can also supply a dataset ZIP explicitly:

```powershell
python run_all.py --dataset-zip ".\dataset-archive\Windows-APT-2025-dataset.zip" --epochs 15
```

## Run individual experiment stages

Run these commands from the repository root. They use the default `outputs/` directory. Run the stages in order because later analyses consume files written by earlier stages.

### 1. Prepare the data

```powershell
python data_pipeline.py --dataset-zip ".\dataset-archive\Windows-APT-2025-dataset.zip" --output-dir ".\outputs"
```

If your dataset is already extracted, use `--data-dir` instead of `--dataset-zip`:

```powershell
python data_pipeline.py --data-dir ".\data\Windows-APT 2025 A Dataset for APT-Inspired Attack" --output-dir ".\outputs"
```

### 2. Train and evaluate prediction models — Table II

```powershell
python train_evaluate.py --prepared ".\outputs\prepared_data.npz" --output-dir ".\outputs" --epochs 15
```

### 3. Calculate lead time and coverage — Table III

```powershell
python lead_time_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --output-dir ".\outputs"
```

### 4. Run attention-masking faithfulness analysis — Table IV

```powershell
python faithfulness_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --checkpoint ".\outputs\gru_attention.pt" --output-dir ".\outputs"
```

```powershell
python ablation_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --output-dir ".\outputs" --epochs 15
```

If a command reports a missing file, verify that the preceding stage completed successfully and that all stages use the same output directory.

## Experimental protocol

The main configuration is recorded in `config.py` and includes:

- 12 selected ATT&CK technique classes from the manuscript's Table I.
- Five October/November period files in the training pool and eleven December period files in the test pool.
- An 80/20 chronological split within the training pool for training and validation.
- Maximum prefix length of 15 events.
- Random seed 42.
- GRU embedding dimension 32, hidden dimension 64, and dropout 0.30.
- Adam learning rate 0.001, batch size 256, and a maximum of 15 epochs with early stopping.
- Sustained-warning confidence threshold of 0.50 for two consecutive prefix extensions.
- Bounded lead-time analysis of up to 250 target instances per technique and up to 20 candidate prefix positions per target.
- Faithfulness analysis on up to 200 correctly classified examples.

Use `outputs/preprocessing_diagnostics.json` to check the data counts and generated prefix-target samples for a specific run.

## Manuscript reference results

The following values are **reference results printed in the associated manuscript**. They are included for comparison and are not hard-coded as the output of the Python scripts.

### Main model comparison (manuscript Table II)

| Model | Macro-F1 | Top-3 accuracy | Macro FPR |
|---|---:|---:|---:|
| Most Frequent | 0.0437 | 0.3884 | 0.0833 |
| Markov (1st order) | 0.3275 | 0.8274 | 0.0558 |
| Markov (2nd order) | 0.3953 | 0.8444 | 0.0545 |
| Causal Transformer | 0.3698 | 0.8571 | 0.0541 |
| GRU + Attention | 0.3285 | 0.8563 | 0.0567 |

In the manuscript's reported run, Markov-2 has the highest Macro-F1, while the causal Transformer has the highest Top-3 accuracy and lowest macro FPR. The GRU-attention model is not the best on every predictive metric.

### Early-warning lead time (manuscript Table III)

| Technique | Median lead (seconds) | Coverage (%) |
|---|---:|---:|
| Ingress Tool Transfer | 498.18 | 93.17 |
| Windows Command Shell | — | 0.00 |
| Modify Registry | 9.50 | 12.85 |
| Account Discovery | 3.04 | 62.98 |
| Lateral Tool Transfer | 15.71 | 73.39 |
| Valid Accounts | 5075.39 | 50.40 |
| Scheduled Task | 2975.01 | 37.20 |
| Command and Scripting Interpreter | — | 0.00 |

| Stored Data Manipulation | — | 0.00 |
| File Deletion | — | 0.00 |

A dash means that no qualifying sustained warning was observed in the evaluated sample, so the median lead time is undefined.

### Attention-masking faithfulness (manuscript Table IV)

| Condition | Average predicted-class probability | Probability drop |
|---|---:|---:|
| Unmasked baseline | 0.6836 | 0.0000 |
| Top-1 attention position masked | 0.5295 | 0.1541 |
| Top-2 attention positions masked | 0.4258 | 0.2578 |
| Random position masked | 0.6519 | 0.0317 |

These results indicate functional dependence on the selected temporal positions for the evaluated examples; they do not independently prove causal explanations.

### GRU ablation and prefix sensitivity (manuscript Table V)

| Configuration | Macro-F1 | Top-3 accuracy |
|---|---:|---:|
| GRU without attention | 0.3722 | 0.8738 |
| GRU with attention | 0.3285 | 0.8563 |
| Short prefix (k ≤ 3) | 0.3270 | 0.8382 |
| Medium prefix (k ≤ 6) | 0.3450 | 0.8712 |
| Long prefix (k ≤ 10) | 0.3283 | 0.8837 |

The manuscript's reported ablation shows that attention did not improve the GRU's raw predictive metrics in that run. Its role is evaluated separately through the attention-masking analysis.

## Limitations

- The primary evaluation is a temporal split, not a scenario-disjoint split.
- The manuscript reports a single random seed (42); it does not establish variability across repeated seeds.
- The study focuses on 12 frequently represented techniques rather than all 45 technique labels noted after annotation expansion.
- The dataset consists of controlled APT-inspired Windows scenarios, so results should not be assumed to transfer directly to every enterprise environment.
- Some implementation details were not fully specified in the manuscript. Differences in preprocessing, target resolution, sampling, or model settings can change the metrics.
- Attention weights and masking results should not be described as proof of causal explanations.

This is a research and evaluation project, not a production-ready endpoint detection product.
