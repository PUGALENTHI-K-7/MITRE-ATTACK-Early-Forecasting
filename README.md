# Explainable Early Forecasting of Next MITRE ATT&CK Techniques

A Python research project that studies whether the **next distinct MITRE ATT&CK technique** can be forecast from a partial, chronologically ordered sequence of Windows host events.

The project is associated with the research manuscript:

> **Explainable Early Forecasting of Next MITRE ATT&CK Techniques from Partial Windows Host-Event Sequences**

The experiments use the **Windows-APT 2025** dataset and compare simple frequency and Markov baselines with neural sequence models. They also evaluate early-warning lead time, warning coverage, attention-masking faithfulness, and model ablations.

> **Reproducibility note:** The manuscript reports result values and key experimental settings, but does not supply the original implementation source code or specify every implementation choice. This repository implements an explicit, repeatable protocol consistent with the manuscript; a new run may produce different numerical results. Use the outputs generated by your own run as the actual experimental results.

## What the project does

Given a prefix of Windows host-event observations, the pipeline attempts to predict the next distinct technique label from a selected set of 12 MITRE ATT&CK techniques. It evaluates prediction quality and whether a warning can be produced before the target technique appears.

### Models evaluated

1. **Most Frequent** — a simple reference baseline.
2. **First-order Markov model** — estimates the next technique using one preceding technique.
3. **Second-order Markov model** — estimates the next technique using up to two preceding techniques.
4. **Causal Transformer** — a neural sequence baseline that uses causal attention.
5. **GRU with temporal attention** — the attention-equipped recurrent model used for temporal explanation analysis.
6. **GRU without attention** — used for the attention ablation experiment.

### Evaluation groups

- **Prediction performance:** Macro-F1, Top-3 accuracy and macro false-positive rate.
- **Early warning:** median lead time and coverage per target technique.
- **Explanation faithfulness:** compare prediction probabilities after masking attention-ranked positions against random-position masking.
- **Ablation and prefix sensitivity:** compare GRU variants and performance for different maximum prefix lengths.

## Requirements

- Windows, Linux or macOS
- Python 3.10 or later recommended
- Internet access for installing the Python dependencies and downloading the dataset
- Sufficient free disk space for the extracted CSV files, prepared data and result files

The neural models can be run on a CPU; a GPU is not required. Execution time depends on your computer and the selected number of epochs.

### Install on Windows with VS Code

Open a terminal in the repository root—the same directory that contains `run_all.py`—and execute:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell prevents environment activation, use the virtual environment's Python executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Run the complete experiment

### Recommended folder layout

If the dataset folder is at `data/Windows-APT 2025 A Dataset for APT-Inspired Attack/`, run the full experiment with the manuscript's maximum of 15 epochs:

```powershell
python run_all.py --epochs 15
```

### If the dataset folder is kept in the repository root

Your local folder may instead look like this:

```text

├── Windows-APT 2025 A Dataset for APT-Inspired Attack/

```

In that case, provide the path explicitly:

```powershell
python run_all.py --data-dir ".\Windows-APT 2025 A Dataset for APT-Inspired Attack" --epochs 15
```

### Quick smoke test

To check that the pipeline can load the data and finish all stages before starting the longer run, use two epochs:

```powershell
python run_all.py --epochs 2
```

Or, if the dataset is in the repository root:

```powershell
python run_all.py --data-dir ".\Windows-APT 2025 A Dataset for APT-Inspired Attack" --epochs 2
```

A two-epoch run is only a workflow check. **Do not substitute its results for the full experiment in the paper.**

You can select a different output directory by adding `--output-dir ".\my_outputs"`.

## Run individual experiment stages

Run these commands from the repository root. The examples assume the recommended dataset path and the default `outputs/` directory. Run each stage in order, because later stages use files created earlier.

### 1. Prepare the data

```powershell
python data_pipeline.py --data-dir ".\data\Windows-APT 2025 A Dataset for APT-Inspired Attack" --output-dir ".\outputs"
```

### 2. Train and evaluate the prediction models — Table II

```powershell
python train_evaluate.py --prepared ".\outputs\prepared_data.npz" --output-dir ".\outputs" --epochs 15
```

### 3. Calculate lead time and coverage — Table III

```powershell
python lead_time_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --output-dir ".\outputs"
```

### 4. Run the attention-masking faithfulness analysis — Table IV

```powershell
python faithfulness_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --checkpoint ".\outputs\gru_attention.pt" --output-dir ".\outputs"
```

### 5. Run the GRU ablation and prefix-sensitivity experiment — Table V

```powershell
python ablation_analysis.py --prepared ".\outputs\prepared_data.npz" --evaluation ".\outputs\evaluation_bundle.npz" --output-dir ".\outputs" --epochs 15
```

If any command reports that a required file is missing, check that the previous stage completed successfully and that all commands use the same output directory.

## Experimental protocol

The configuration in `config.py` records the selected techniques, training/test period files and core hyperparameters. The implementation uses:

- 12 selected ATT&CK techniques from the paper's Table I.
- Five October/November period files for the training pool and eleven December period files for the test pool.
- A chronological 80/20 split within the training pool for training and validation.
- Maximum prefix length: 15 events.
- Random seed: 42.
- GRU embedding dimension: 32; hidden dimension: 64; dropout: 0.30.
- Adam learning rate: 0.001; batch size: 256; maximum of 15 epochs with early stopping.
- A sustained-warning confidence threshold of 0.50 for two consecutive prefix extensions.
- Bounded lead-time analysis of up to 250 target instances per technique and up to 20 candidate prefix positions per target.
- Faithfulness analysis on up to 200 correctly classified examples.

Check `config.py` for the exact configuration used by the current code. The `outputs/preprocessing_diagnostics.json` file is especially important for checking the number of events, streams and generated prefix-target pairs.

## Results reported in the manuscript

The following are **reference values printed in the current manuscript**, provided to help readers understand the research question. They are not a promise that a new run of this implementation will reproduce the same decimals.

### Main model comparison

| Model | Macro-F1 | Top-3 accuracy | Macro FPR |
|---|---:|---:|---:|
| Most Frequent | 0.0437 | 0.3884 | 0.0833 |
| Markov (1st order) | 0.3275 | 0.8274 | 0.0558 |
| Markov (2nd order) | 0.3953 | 0.8444 | 0.0545 |
| Causal Transformer | 0.3698 | 0.8571 | 0.0541 |
| GRU + Attention | 0.3285 | 0.8563 | 0.0567 |

In the manuscript's current run, Markov-2 has the highest Macro-F1, while the causal Transformer has the highest Top-3 accuracy and lowest macro FPR. The GRU-attention model is not the best model on every predictive metric.

### Attention-masking reference values

| Condition | Average predicted-class probability | Probability drop |
|---|---:|---:|
| Unmasked baseline | 0.6836 | 0.0000 |
| Top-1 attention position masked | 0.5295 | 0.1541 |
| Top-2 attention positions masked | 0.4258 | 0.2578 |
| Random position masked | 0.6519 | 0.0317 |

These results are evidence of functional dependence on selected positions in the tested examples; they do not independently prove causal explanations.

### GRU ablation reference values

| Configuration | Macro-F1 | Top-3 accuracy |
|---|---:|---:|
| GRU without attention | 0.3722 | 0.8738 |
| GRU with attention | 0.3285 | 0.8563 |
| Short prefix (k ≤ 3) | 0.3270 | 0.8382 |
| Medium prefix (k ≤ 6) | 0.3450 | 0.8712 |
| Long prefix (k ≤ 10) | 0.3283 | 0.8837 |

The manuscript's reported ablation shows that attention does not improve the GRU's raw predictive scores in that run. Its role is evaluated separately through attention-masking analysis.

## Limitations and responsible interpretation

- The primary evaluation is a **temporal split**, not a scenario-disjoint split.
- The manuscript reports a single random seed (42); it does not establish variability across repeated seeds.
- The study focuses on 12 frequently represented techniques, rather than all 45 technique labels present after annotation expansion.
- The dataset consists of controlled APT-inspired Windows scenarios, so results should not be assumed to transfer directly to every enterprise environment.
- Some implementation details were not fully specified in the manuscript. Differences in preprocessing, target resolution, smoothing, sampling or model settings can change the resulting metrics.
- Attention weights and masking results should not be described as proof of causal explanations.

This is a research and evaluation project, not a production-ready endpoint detection product.
